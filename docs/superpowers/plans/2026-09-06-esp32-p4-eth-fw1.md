# ESP32-P4-ETH FW-1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Conectar la Waveshare ESP32-P4-ETH física al WebSocket V1 existente mediante Ethernet, challenge/HMAC, status, heartbeat y reconexión automática.

**Architecture:** La aplicación física vive en `firmware/esp32-p4` y reutiliza los componentes neutrales bajo `firmware/components`. Un supervisor es el único dueño del estado; Ethernet y WebSocket publican eventos, mientras configuración, autenticación y codec JSON permanecen aislados y probables.

**Tech Stack:** ESP-IDF 5.5.4, ESP32-P4 v1.3, FreeRTOS, esp_eth/IP101GR, esp_netif, esp_http_server, NVS, mbedTLS, cJSON, `espressif/esp_websocket_client` 1.8.0, Unity, pytest, FastAPI y Next.js.

**Spec:** `docs/superpowers/specs/2026-09-06-esp32-p4-eth-fw1-design.md`

## Global Constraints

- Unidad exacta: Waveshare ESP32-P4-POE-ETH SKU 32088, o placa base SKU 32086
  con módulo PoE oficial Waveshare, ESP32-P4 revisión física v1.3, COM3.
- La operación y aceptación usan red y alimentación por el mismo cable PoE;
  USB Type-C queda sólo para flasheo/diagnóstico y se desconecta en pruebas PoE-only.
- No usar inyectores PoE pasivos ni fuentes fuera de las especificaciones del módulo.
- Compilar con ESP-IDF 5.5.4, target `esp32p4`, `CONFIG_ESP32P4_SELECTS_REV_LESS_V3=y` y `CONFIG_ESP32P4_REV_MIN_100=y`.
- PHY IP101GR/RMII: MDC 31, MDIO 52, reset 51, clock input 50, TX_EN 49, TXD0 34, TXD1 35, CRS_DV 28, RXD0 29, RXD1 30 y dirección 1.
- FW-1 usa sólo una URL completa como `ws://192.168.1.20:8000/ws/device`
  dentro de la LAN; rechaza `wss://` hasta implementar CA y hostname.
- FW-1 anuncia `capabilities: []` y no implementa audio, PAUD, cámara, pulsador ni OpenAI.
- No modificar el backend para acomodar el firmware.
- No guardar secretos en código, `sdkconfig`, comandos, logs, fixtures de integración ni commits.
- No imprimir cadena canónica, digest, token de upload ni contenido sensible.
- El NVS sin cifrado y la consola USB de FW-1 son exclusivamente de laboratorio:
  no protegen el secreto frente a extracción física y no son el diseño de producción.
- Todos los cambios funcionales siguen RED-GREEN-REFACTOR y terminan en un commit revisable.
- No afirmar compilación, ejecución Unity o prueba física sin conservar la salida real del comando correspondiente.

## File Map

### Shared firmware

- `firmware/components/device_protocol/include/device_protocol.h`: estados, secuencia y backoff neutrales.

- `firmware/components/hardware_hal/`: frontera neutral existente, sin pines físicos.

### Physical application

- `firmware/esp32-p4/main/app_main.c`: composición de subsistemas.
- `firmware/esp32-p4/main/app_supervisor.[ch]`: única máquina de estado y manejo de eventos.
- `firmware/esp32-p4/main/provisioning_console.[ch]`: flujo USB interactivo sin eco.

- `firmware/esp32-p4/main/network_manager.[ch]`: enlace, DHCP y eventos de red.
- `firmware/esp32-p4/main/websocket_transport.[ch]`: conexión, reensamblado y envío.
- `firmware/esp32-p4/main/command_handler.[ch]`: status request, camera rejection y comandos desconocidos.
- `firmware/esp32-p4/components/board_port/`: configuración exclusiva Waveshare/IP101GR.

### Tests and evidence

- `firmware/test_apps/device_protocol/`: ampliar pruebas de estado y secuencia.
- `firmware/test_apps/fw1_components/`: Unity para config, auth, codec, comandos y backoff.

- `firmware/esp32-p4/README.md`: build, provisioning, flash, monitor y aceptación.
- `docs/verification/esp32-p4-eth-fw1.md`: evidencia fechada de toolchain, compilación y hardware.

### Task 5: Encode and parse the strict FW-1 JSON subset

**Files:**
- Create: `firmware/components/portero_codec/CMakeLists.txt`
- Create: `firmware/components/portero_codec/include/portero_codec.h`
- Create: `firmware/components/portero_codec/portero_codec.c`

**Interfaces:**
- Produces typed encoders for hello, auth response, status, heartbeat, command ACK and command result.
- Produces typed parsers for auth challenge, auth ok and command request.

```c
#define PORTERO_JSON_MAX_BYTES 12288
#define PORTERO_COMMAND_ID_CAPACITY 37
#define PORTERO_COMMAND_NAME_CAPACITY 65
#define PORTERO_NONCE_CAPACITY 129
#define PORTERO_UPLOAD_TOKEN_CAPACITY 513

typedef enum {
    PORTERO_SERVER_AUTH_CHALLENGE,
    PORTERO_SERVER_AUTH_OK,
    PORTERO_SERVER_COMMAND_REQUEST,
} portero_server_message_type_t;

typedef enum { PORTERO_ETHERNET_ONLINE, PORTERO_ETHERNET_OFFLINE,
               PORTERO_ETHERNET_ERROR } portero_ethernet_state_t;
typedef enum { PORTERO_PERIPHERAL_READY, PORTERO_PERIPHERAL_UNAVAILABLE,
               PORTERO_PERIPHERAL_ERROR } portero_peripheral_state_t;
typedef enum { PORTERO_ACK_ACCEPTED, PORTERO_ACK_REJECTED } portero_ack_status_t;
typedef enum { PORTERO_RESULT_COMPLETED, PORTERO_RESULT_FAILED } portero_result_status_t;

typedef struct {
    const char *boot_id;
    uint64_t seq;
    const char *device_id;
} portero_hello_t;

typedef struct {
    const char *boot_id;
    uint64_t seq;
    const char *nonce;
    const char *digest;
} portero_auth_response_t;

typedef struct {
    const char *boot_id;
    uint64_t seq;
    const char *firmware_version;
    const char *hardware_model;
    uint64_t uptime_seconds;
    portero_ethernet_state_t ethernet;
    portero_peripheral_state_t camera;
    portero_peripheral_state_t microphone;
    portero_peripheral_state_t speaker;
    uint32_t free_heap_bytes;
} portero_status_t;

typedef struct {
    const char *boot_id;
    uint64_t seq;
    uint64_t uptime_seconds;
} portero_heartbeat_t;

typedef struct {
    const char *boot_id;
    uint64_t seq;
    const char *command_id;
    portero_ack_status_t status;
    const char *error_code;
} portero_command_ack_t;

typedef struct {
    const char *boot_id;
    uint64_t seq;
    const char *command_id;
    portero_result_status_t status;
    const char *result_json;
    const char *error_code;
} portero_command_result_t;

typedef struct {
    char command_id[PORTERO_COMMAND_ID_CAPACITY];
    char command[PORTERO_COMMAND_NAME_CAPACITY];
    char payload_json[8193];
} portero_command_request_t;

typedef struct {
    portero_server_message_type_t type;
    union {
        struct {
            char algorithm[12];
            char nonce[PORTERO_NONCE_CAPACITY];
            char expires_at[40];
        } auth_challenge;
        struct {
            char upload_token[PORTERO_UPLOAD_TOKEN_CAPACITY];
            char upload_expires_at[40];
            uint32_t heartbeat_interval_seconds;
        } auth_ok;
        portero_command_request_t command_request;
    } body;
} portero_server_message_t;

esp_err_t portero_encode_hello(const portero_hello_t *message,
                               char *out, size_t capacity, size_t *written);
esp_err_t portero_encode_auth_response(const portero_auth_response_t *message,
                                       char *out, size_t capacity, size_t *written);
esp_err_t portero_encode_status(const portero_status_t *message,
                                char *out, size_t capacity, size_t *written);
esp_err_t portero_encode_heartbeat(const portero_heartbeat_t *message,
                                   char *out, size_t capacity, size_t *written);
esp_err_t portero_encode_command_ack(const portero_command_ack_t *message,
                                     char *out, size_t capacity, size_t *written);
esp_err_t portero_encode_command_result(const portero_command_result_t *message,
                                        char *out, size_t capacity, size_t *written);
esp_err_t portero_parse_server_message(const char *json, size_t length,
                                       portero_server_message_t *message);
```
