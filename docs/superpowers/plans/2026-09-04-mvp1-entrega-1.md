# Portero Inteligente MVP1 — Entrega 1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Entregar un sistema local end-to-end que administre usuarios, viviendas y dispositivos, autentique un simulador mediante HMAC, procese presencia/comandos/capturas y lo exponga en un panel Next.js.

**Architecture:** Monorepo con PostgreSQL en Docker, FastAPI como autoridad de seguridad y coordinación, Next.js como panel y un simulador Python que implementa el protocolo de dispositivo V1. Las conexiones activas permanecen en memoria y todo estado durable se guarda en PostgreSQL; los JPEG se guardan bajo una interfaz de filesystem.

**Tech Stack:** Python 3.12+, FastAPI, SQLAlchemy 2.x, Alembic, Pydantic 2, PostgreSQL 16, pytest, Next.js App Router, React, TypeScript, Tailwind CSS, shadcn/ui, React Hook Form, Zod, Recharts y la versión exacta de ESP-IDF compatible con el BSP y los ejemplos de la placa seleccionada.

**Spec:** `docs/superpowers/specs/2026-09-04-mvp1-entrega-1-design.md`

## Global Constraints

- El repositorio vive directamente en `C:\Portero` y los comandos documentados deben funcionar en PowerShell.
- PostgreSQL es la única base principal; no usar SQLite en aplicación ni pruebas.
- El frontend nunca se comunica directamente con el ESP32 o simulador.
- Las sesiones web usan cookie HttpOnly y token opaco cuyo hash se persiste.
- Las autorizaciones se resuelven por usuario, vivienda y permiso.
- El secreto del dispositivo se cifra de forma autenticada y sólo se muestra al aprovisionar.
- El protocolo usa challenge de un solo uso, HMAC-SHA256, `boot_id`, `seq` y `command_id` UUID.
- No almacenar cada heartbeat; persistir únicamente la instantánea actual y los cambios relevantes.
- JPEG y audio no se codifican como Base64 entre dispositivo y backend.
- Ningún secreto se registra ni se incluye en frontend o firmware.
- No inventar GPIO, PHY, I2S, cámara ni revisión de placa.
- Ejecutar Uvicorn con `--workers 1` en MVP1; el registro WebSocket y los tokens de upload viven en memoria.
- No actualizar ESP-IDF automáticamente; fijar la versión indicada por el BSP y los ejemplos compatibles con la placa seleccionada.
- Cada cambio de producción se desarrolla con una prueba que falle primero.
- Cada tarea termina con pruebas verdes y un commit pequeño.
